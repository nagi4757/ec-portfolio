# P3-a host document contract

`ssm-documents/od-readiness.yaml` and `spot-smoke.yaml` are JSON documents (a
subset of YAML), generated by `python3 -B scripts/ssm/ssm_documents.py`. They embed
`scripts/ssm/ssm_runtime.py` verbatim. No new host helper installation, TLS repair,
deployment, EC2 operation, ENI operation, or EIP operation is performed.

Both documents require these `String` parameters. SendCommand must use the
reviewed values from the state machine, never values from an EventBridge event.

| Parameter | Contract |
| --- | --- |
| `expectedImageSha` | Exact 40 lowercase hexadecimal SHA extracted from the live production TD image |
| `expectedImageRepository` | Exact production ECR URL, account-bound, `ap-northeast-1`, repository `ec-portfolio-demo-api` |
| `expectedTaskDefinitionArn` | Exact current production TD ARN and revision, same account as ECR |
| `checkMode` | `local` before EIP promotion; `endToEnd` after association readback |
| `cloudFrontDomain` | The configured distribution domain, not a URL or event-supplied hostname |

The plugin timeout is 300 seconds; callers must provide a sufficient bounded
poll deadline and require successful command completion and response code zero.
Document stdout is one JSON result containing `result`, `document`, `checkMode`,
and `imageSha`. Failures produce fixed diagnostics without raw host responses,
container configuration, TLS material, or the origin verification secret.

All parameters use `interpolationType: ENV_VAR`. The shell quotes every value
and starts Python with a clean environment and isolated mode. There is no
textual `{{ parameter }}` interpolation, eval, shell command parameter, path
parameter, secret parameter, or fallback shell substitution. SSM Agent
3.3.2746.0 or newer is required for ENV_VAR support. An older agent fails for
unset variables. This minimum is confirmed by the [AWS parameter handling
documentation](https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-troubleshooting.html)
and [document parameter reference](https://docs.aws.amazon.com/systems-manager/latest/userguide/documents-syntax-data-elements-parameters.html).

The On-Demand check requires a completed successful convergence invocation in
this boot, the exact full ECR image reference, running API and Valkey, and the
existing private Docker port contract. The Spot check requires both bootstrap
markers, ECS active, exactly one API container, the expected production cluster,
family, revision, image reference, host network mode, and loopback-only API and
Valkey listeners. It rejects the measurement cluster/family.

Both require readiness UP, Nginx active, no port 80 listener, and HTTPS against
loopback with the real origin SNI. Python verifies the served certificate and
hostname with the system CA store and requires its actual notAfter to be at
least 14 days away. Requests without or with a bad verification token must
return 403, while a valid token must return 200 and readiness UP. The token is
read from the existing SecureString using the instance identity and a clean
AWS CLI environment, kept in memory, and sent only to loopback HTTPS. It never
appears in a command line, environment of a child, or document output.

`endToEnd` additionally checks CloudFront readiness and performs a public GET
on `/api/public/categories` with a fresh UUID correlation ID. It requires the
echoed response ID and an exact local API log record for that ID, method, path,
status, and completion message. A remote HTTP 200 cannot attest this host.
Read retries are bounded to five attempts; missing, duplicate, delayed beyond
the bound, malformed, or unobservable proof fails closed.

Source basis is repository commit `1e6c1743bbbfc201d5497e0f7e9980ae743be827`:
`CorrelationIdFilter.kt` logs ordinary request completion, while successful
health probes are intentionally excluded. `CategoryPublicController.kt` exposes
the public categories GET. `application-demo.properties` enables structured
console logging. The existing CloudFront origin request policy forwards
`X-Correlation-ID` and query strings, with caching disabled. The Nginx log
format does not include a correlation ID, so this implementation does not
invent Nginx correlation evidence.

Live host behavior is NOT VERIFIED. P3-b must verify the agent version, the live
image's logging contract, local Docker log access with the configured log
driver, the JP/KR-restricted CloudFront route, TLS remaining lifetime, actual
instance permissions and network egress, and bounded command completion.
Missing evidence must not be replaced with a weaker remote-only health check.
No extra host policy or log-reading AWS permission was introduced to hide
those uncertainties. TLS restore remains a separately reviewed operation.
